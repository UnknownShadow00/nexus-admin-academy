## 1. What Is Complete and Working

- **Auth separation** — student JWT (httpOnly cookies, `RequireAuth`) vs admin session
  (`AdminAccessGate`, `/admin-login`) vs mentor read-all. Seeding via `scripts/seed_users.py`.
  No public registration, as designed.
- **Core student loop** — learning path with YouTube embeds + watch tracking, quiz engine
  (ExamCompass scrape + transcript→MCQ generation), multi-select questions, ticket system with
  plain-English explanation grading, XP/streak/leaderboard, study tracker.
- **Flashcards** — SM-2 scheduling (`fsrs_service.py`), auto-card creation from wrong quiz
  answers, `FlashcardReviewPanel` on StudentHome.
- **Labs/capstones application layer** — `LabTemplate`/`LabRun`/`CapstoneTemplate`/`CapstoneRun`
  models, evidence upload, admin CRUD UIs (`/admin/labs`, `/admin/capstones`).
- **Proxmox/Guacamole integration code** — `proxmox_service.py` (clone/start/IP/destroy),
  `guacamole_service.py` (connection create/delete), `VmAssignment` tracking, lab submit
  teardown, admin idle-cleanup endpoint. Code-complete but **never smoke-tested against real
  infrastructure** and carries the P0 bugs in section 2.
- **Admin panel** — student manager, quiz editor with publish/draft, curriculum editor,
  ticket review queue, AI cost dashboard, speed-flagged quiz attempts view.
- **Schema maturity** — 29 Alembic migrations, consistent model layout, backend regression
  tests pass (35 tests as of 2026-05-30).

## 2. What Is Broken (P0 — fix before anything else)

1. **Guacamole client URL encoding is wrong** — `guacamole_service.py:62` builds
   `base64("c/{conn_id}")`. Guacamole requires `base64("{identifier}\0c\0{datasource}")`
   (NUL-separated, datasource e.g. `postgresql`). The lab iframe cannot render until fixed.
2. **Students receive the Guacamole ADMIN token** — `get_token_url` authenticates as
   `GUACAMOLE_ADMIN_USER` and embeds that token in the student-facing URL. Any student can
   reach the Guacamole admin UI and every other student's connection. Fix: create a
   per-student (or per-assignment) Guacamole user via REST, grant only its own connection,
   return that user's token.
3. **VM provisioning blocks the request worker** — `labs.py:_provision_vm` synchronously
   clones, starts, and polls `get_vm_ip` for up to 120s+; the frontend axios timeout is 30s.
   Every real lab start will time out client-side while the single worker is pinned. Fix:
   return `202 provisioning` immediately, background-task the provisioning, add
   `GET /api/labs/{id}/vm-status` polling, render iframe on `running`.
4. **VM session unrecoverable after refresh** — `guacUrl` exists only in `LabPage.jsx` React
   state. A page refresh during `in_progress` permanently locks the student out of their
   running VM. `GET /labs/{id}` must return existing connection info.
5. **Phantom seed students** — `main.py:65 seed_students()` creates 5 credential-less students
   (Alex/Jordan/Sam/Taylor/Riley) on any empty DB, polluting leaderboard/squad/cohort stats
   and conflicting with `scripts/seed_users.py` (the only intended seeder). Remove it and
   purge ghost rows from existing DBs.
6. **App fails to boot without `OPENROUTER_MODEL`** — `ai_service.py:34` raises at import
   time; import chain `main → tickets → ticket_grader → ai_service` means the entire app dies,
   not just AI features. Move the check into `call_ai()`.
7. **Railway ephemeral-disk data risk** — uploads (`labs.py`, `tickets.py`, `evidence.py`)
   write to local disk; Railway FS is wiped on redeploy. Mount a Railway volume for
   `UPLOAD_DIR` or use Supabase Storage; confirm prod `DATABASE_URL` is Supabase, not SQLite.

## 3. Security / Correctness Issues (P1)

1. **Bearer-anything auth bypass** — `admin_auth.py:108 allow_admin_or_student` returns `True`
   for any `Authorization: Bearer <anything>` without decoding the JWT (verified still present).
   Used by study-tracker curriculum endpoints. Decode the token or require `get_current_student`.
2. **Multi-select grading bug** — `quizzes.py:submit_quiz`: a single-letter answer to a
   multi-select question passes the `in correct_letters` check → full credit for a partial
   answer. Compare as sets when `is_multi_select`.
3. **Weak admin session** — token is unsalted deterministic `sha256(password)`, no server-side
   expiry, non-constant-time `==` comparisons, and auth logs leak secret lengths. Use a
   random/signed token, `secrets.compare_digest`, drop length logging.
4. **Evidence upload gaps** — lab evidence and `evidence.py` have no file-size cap (tickets
   caps at 5MB); `evidence.py` lets any student attach evidence to any `ticket_id`. Also
   `EvidenceArtifact.submission_id` means ticket_id for tickets but lab_run_id for labs —
   document or fix the overload.
5. **Quiz retakes overwrite history** — a retake overwrites the single `QuizAttempt` row, so
   the "attempts" list is fiction and speed-flag evidence can be laundered by one slow retake.
   Insert a new row per attempt.
6. **localStorage mentor admin shell** — `AdminAccessGate.jsx` renders admin pages when
   client-writable `selected_profile.is_mentor` is true, contradicting "mentor cannot access
   admin panel." Backend APIs already block it; clean up the gate so the UI matches.

## 4. What Is Missing Entirely

- **Sidecar deployments** (outside this repo, on Proxmox): Guacamole, GLPI, Gitea, n8n,
  Netdata/Uptime Kuma. Guacamole is the blocking one — VM labs cannot be smoke-tested without it.
- **Idle-VM cleanup scheduler** — endpoint exists (`DELETE /api/admin/vms/cleanup`); nothing
  calls it on cadence.
- **Real end-to-end VM lab smoke test** — the whole Proxmox path is only exercised by mocks.
- **Ollama AI backend** — code is hardwired to OpenRouter; base URL is the easy swap point.
- **Content**: Active Directory lab template family (biggest job-readiness gap), parametrized
  ticket variants, escalation-type tickets.

## 5. Code Quality Issues (P3)

- `admin_content.py` admin CRUD takes raw dicts everywhere — no Pydantic validation at the boundary.
- `python-jose` + fallback crypto shims in `auth_service.py` — replace with PyJWT and delete shims.
- Dead frontend code: `SelectProfile.jsx`, `components/Dashboard.jsx`, `QuizList.jsx`,
  `Leaderboard.jsx`, `tmp_bookmarklet.js`.
- Hardcoded `week_number = 1` in `students.py` stats.
- `AIRateLimit` rows grow unbounded — needs pruning.
- Mixed HTTP clients: `guacamole_service.py` uses `requests`, everything else `httpx`.
- `datetime.utcnow()` (deprecated, naive) across rate_limiter, activity_service, admin_content,
  students, tickets; `ai_service._today_window()` uses local time for the daily budget window —
  both will bite at the Supabase/Postgres cutover.

## 6. Performance / Resource Usage (P2)

- **Playwright in prod requirements** — only used for occasional admin scraping; bloats the
  Railway image substantially. Move to `requirements-dev.txt` or run locally.
- **Full VM clones** — `proxmox_service.clone_template` uses `full=1`; linked clones provision
  in seconds and cost near-zero disk.
- **Frontend bundle >500kB** — 11 admin pages eagerly bundled; `React.lazy` them.
- **Blocking provisioning** (also P0 #3) — pins the lone Railway worker for minutes per lab start.

## 7. Dependency / Tooling Health

- `python-jose` is the weakest dependency (maintenance state, shims) — PyJWT swap queued in P3.
- Doc drift found during audit was fixed same day: CLAUDE.md claimed Anthropic AI and listed

## 9. Platform Vision (Phase 4 — ideas, no code)

- **Active Directory lab family first.** Windows Server AD DS + domain-joined client:
  password resets, lockouts, group membership, GPO, share access. This is the single
  highest-value content gap for help-desk hiring — most real tickets are AD tickets.
- **Anti-cheat through parametrization, not policing.** Reuse the `break_script` JSON pattern
  to give each student a different broken value (different DNS server, different locked
  account). Sharing answers stops working when answers differ; zero ongoing mentor effort.
- **Escalation-type tickets.** Some tickets' correct answer is a clean escalation note, not a
  fix. That's a real job skill nobody practices. Grade the note.
- **Grade `commands_used` and occasional "write the email to the user."** Communication
  grading is cheap with the existing AI grader and maps directly to interviews.
- **Anki export of missed questions** (`genanki`) — leverage existing wrong-answer data;
  students study on phones without you building a mobile UI.
- **Resource aggregation strategy:** don't build courses. Curate Professor Messer / free
  courseware into the existing Module/Lesson/CurriculumVideo structures with watch tracking —
  the platform's value is structure + accountability, not content.
- **GLPI as student-facing ticketing** (P4) — practicing in a real ITSM tool is résumé-ready;
  consider Nexus↔GLPI scenario sync only if it stays low-maintenance.
- **Skip:** building your own course content, gamification beyond existing XP, anything that
  adds weekly mentor burden beyond the ~2-hour budget. Weekly mentor digest
  (`/api/admin/weekly-summary` → Discord via n8n) is the one automation worth adding.

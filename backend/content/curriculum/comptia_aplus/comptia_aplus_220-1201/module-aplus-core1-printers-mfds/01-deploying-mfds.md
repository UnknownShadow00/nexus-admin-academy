# 1. What is this?
A multifunction device (MFD) can print, scan, copy, and sometimes fax. Deployment includes more than plugging it in: choose a suitable location, connect by USB/Ethernet/Wi-Fi, install a compatible driver, verify firmware/policy, and configure defaults such as duplex, orientation, trays, and print quality.

# 2. Why does an IT worker care?
Printers are shared business tools. A bad deployment can create hundreds of repeated tickets: wrong driver, wrong tray, unreachable IP, insecure defaults, or scanning that was never configured.

# 3. Watch / Read
**Required:** Professor Messer — *Multifunction Devices (220-1201)*.

# 4. What you actually need to remember
- Confirm physical location, power, network/USB method, and user workflow before configuration.
- Use supported drivers/firmware. Printer languages may include **PCL** or **PostScript** depending on device/workflow.
- Configure duplex/orientation/tray/paper/quality defaults intentionally.
- A network printer should have stable addressing/discovery according to organizational design; do not invent an unmanaged static address that can conflict.
- Print a test page before calling deployment complete.

# 5. At work
A new HR MFD is reachable, but every onboarding packet prints from the manual-feed tray. The device is "online" but deployment is not complete until driver/default tray settings match the workflow.

# 6. Commands / Tools
Windows Printers & scanners, printer properties/test page, printer web/admin page where authorized, ping/network evidence from Module 7, and manufacturer documentation.

# 7. Interview / Explain

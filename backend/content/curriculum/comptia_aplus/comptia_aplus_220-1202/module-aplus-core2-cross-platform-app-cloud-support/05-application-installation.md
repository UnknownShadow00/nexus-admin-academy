# Application Requirements, Distribution & Safe Deployment Decisions

## 1. What is this?
Installing software is a compatibility and change decision, not just clicking Next. A+ expects technicians to compare OS/architecture, CPU, RAM, storage, graphics/VRAM, external tokens, distribution methods, and business/device/network/operational impact.

## 2. Why does an IT worker care?
Installing unsupported software can cause crashes, consume scarce resources, break a workflow, or violate organizational standards. The safe answer may be “not supported yet” or “handoff for an approved upgrade.”

## 4. What you actually need to remember
- Check 32-bit/64-bit and application-to-OS compatibility.
- Compare CPU, RAM, storage, graphics/VRAM, and external hardware-token requirements.
- Distribution can be physical media, mountable ISO, downloadable package, or image deployment.
- Consider device, network, operational, and business impact before deployment.
- Use approved sources and deployment methods; do not bypass requirements to satisfy urgency.

## 5. At work
A design app requires a supported 64-bit OS, 16 GB RAM, dedicated graphics, and 6 GB free space. A laptop with 8 GB RAM and integrated graphics does not become compatible because the installer happens to launch.

## 6. Commands / Tools
System information, vendor requirements, free-storage checks, package signatures/source, approved software catalog/deployment system.

## 7. Interview / Explain
Describe the checks you make before approving an application install on an employee’s workstation.

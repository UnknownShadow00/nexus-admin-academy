# Mobile Security Troubleshooting & Compromise Indicators

## 1. What is this?
Recognize jailbreaking/rooting, app spoofing, malicious profiles, unusual data use, degraded performance, connectivity tampering, and other security symptoms.

## 2. Why does an IT worker care?
Phones, browsers, Wi-Fi, and small routers sit directly between users and company data. The support technician must distinguish ordinary configuration failure from a security problem without bypassing management, encryption, certificates, or policy.

## 3. Watch / Read
Complete the required resource **resource.aplus.m14.troubleshooting_mobile_security**. Use supplemental resources only where another vendor-specific view is useful.

## 4. What you actually need to remember
- Unexpected third-party app sources, app spoofing, jailbreak/root indicators, unknown profiles, excessive data use, and persistent redirects can indicate compromise.
- Connectivity loss can be security-related or ordinary misconfiguration; preserve evidence before assuming malware.
- Unknown configuration profiles or certificates on a managed device require investigation and often escalation.
- Use approved mobile-security/MDM evidence and app-store/source checks rather than installing random 'cleaner' apps.
- A compromised corporate device may need isolation, remote lock/wipe, or re-enrollment according to policy.
- Do not bypass compliance checks to restore access.

## 5. At work
- If compromise is plausible, protect corporate accounts/data and document evidence before destructive remediation.
- Escalate when the device has been rooted/jailbroken or management trust cannot be restored safely.

## 6. Commands / Tools
- MDM compliance/profile view
- App source/store history
- Data/battery usage
- Certificate/profile settings
- Network reset (authorized)
- Remote lock/wipe workflow

## 7. Interview / Explain
How do you separate a normal Wi-Fi misconfiguration from a suspicious mobile security issue?

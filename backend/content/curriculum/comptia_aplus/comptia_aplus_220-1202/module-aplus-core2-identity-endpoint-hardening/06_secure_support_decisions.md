# Secure Support Decisions: Elevate, Allow, Deny or Escalate

## 1. What is this?
Combine identity, endpoint, permission, and hardening evidence into a safe support decision.

## 2. Why does an IT worker care?
Security tickets often look like ordinary access or application problems. The technician must restore approved work without weakening controls, granting unnecessary privilege, or destroying useful evidence.

## 3. Watch / Read
Complete the required resource **resource.aplus.m13.authentication_access** before the Quick Check. Use optional references only when you need another explanation or a vendor procedure.

## 4. What you actually need to remember
- A security control causing friction may be working exactly as designed.
- Verify identity, request, approval, publisher/source, current policy, and the minimum required access before remediation.
- Use temporary or scoped privilege when possible; avoid permanent broad access.
- Do not create firewall/AV exclusions without a documented, approved need and a narrow scope.
- Escalation is a correct outcome when the technician lacks authority to alter a policy or privileged control.
- Verification must repeat the user's original business task and confirm the security baseline still holds.

## 5. At work
- Good security support protects both the user's workflow and the control that protects the organization.
- Document what was checked, what changed, who approved it, what was verified, and any remaining risk.

## 6. Commands / Tools
- Ticket/approval workflow
- Windows Security evidence
- Directory/group evidence
- Application publisher/hash/source evidence where approved

## 7. Interview / Explain
A user says 'just make me admin.' Walk through the safer support decision.

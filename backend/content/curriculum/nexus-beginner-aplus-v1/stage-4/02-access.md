## Whose context?

The **signed-in account** is the Windows identity currently being used. A file may be saved under one person's account and absent from another's Documents folder. Ask the user which account is affected. You may inspect the current account name with their permission using the Windows account menu; do not request or record a password. An account name is context, not permission to browse all of that person's files.

**Ownership** means a file or folder belongs to an account or organization according to its rules. **Permissions** control who may read or change it. An **Access denied** message is evidence of a boundary, not proof the file is broken. **Least privilege** means using only the access needed for the approved task. Technical ability to open or change a file is different from authorization to do so.

Do not borrow someone's credentials, use an administrator account without authorization, change permissions to hide an error, or search another person's files without approval. Record the exact boundary in plain language and escalate to the owner or authorized support channel. A mentor can help decide the next approved step.

Open the account-boundary picture and choose a safe action. The checkpoint asks whether an action is authorized, not merely possible.

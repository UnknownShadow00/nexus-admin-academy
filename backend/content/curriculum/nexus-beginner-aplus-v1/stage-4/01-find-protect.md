## Locate before changing

A **save location** is the folder where an application stored a file. A path such as `Documents > Work > schedule.txt` names folders followed by a file. `schedule.txt` is a file, `Work` is a folder, and the application used to open the file is separate. The **extension** after the final dot, such as `.txt`, hints at the file type; it does not prove what is inside.

Ask for the exact name, the expected folder, and the signed-in account. In File Explorer, follow the supplied path under the authorized account and compare the name and extension. If the file is not there, say **not found in the folder checked**. It might be in a different folder; that observation is not proof it is missing from the computer. Search only approved locations, and do not open unrelated personal files.

## Protect the work

**Copy** makes another file while leaving the original in place. **Move** changes its location. Deleting a file may send it to the **Recycle Bin**, but recovery is not guaranteed. These actions can disrupt someone's work; locating a file does not authorize you to copy, move, or delete it. If an application shows unsaved work, ask the user to save it before any action that could close the application. Do not close, restart, or change the file to make an issue disappear.

Open the path picture, then order the safe locating steps. The checkpoint asks what you can and cannot conclude from the folder you checked.

## Worked support note

**Reported:** “I cannot find schedule.txt.” **Checked:** With the user's permission, followed the supplied Documents > Work path in File Explorer. **Found:** The Work folder opened, but schedule.txt was not visible there. **Not verified:** Whether the file is missing from the computer; only one folder was checked. **Next step:** Confirm the expected save location with the user; search another approved location only if authorized.
